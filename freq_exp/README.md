# freq_exp — эксперименты с частотными потерями для PiSA-SR

Всё, что относится к экспериментам по сохранению высоких частот, лежит в этой папке.
Исходные файлы PiSA-SR, включая `train_pisasr_curve_exp.py`, не изменены.
Все команды запускаются из папки `PiSA-SR-main`.

## Установка

```bash
pip install focal-frequency-loss fdl-pytorch lpips pyiqa
```

Результаты пишутся в `$OUT/<имя эксперимента>/` (по умолчанию `experiments/freq/`):

- `curve_<этап>.csv`, `curve.png` — LPIPS, VoL/GT и метрики по ВЧ-полосам по шагам;
- `bands_<этап>.csv` — FRC, ошибка и энергия по восьми кольцам частот;
- `train_log_<этап>.csv` — значение, вес и норма градиента каждого члена потерь;
- `args_<этап>.json` — все параметры запуска;
- `checkpoints/pisasr_pix_final.pkl`, `checkpoints/pisasr_final.pkl` (и `*_ema.pkl`, если включена EMA).

## К6: декодер VAE

```bash
bash freq_exp/experiments.sh E17                       # дообучить декодер; LQ и UNet не нужны
python freq_exp/diag_vae_ceiling.py ... --vae_decoder_ckpt $OUT/E17_K6_vae_ffl/checkpoints/vae_decoder_final.pt
python freq_exp/infer_eval.py ... --vae_decoder_ckpt <тот же файл>      # готовая модель с новым декодером
VAE_DEC=<тот же файл> bash freq_exp/experiments.sh E09                  # обучение UNet с новым декодером
```

- Обучаются `decoder` и `post_quant_conv` (49,5 млн параметров), энкодер заморожен. Латентное пространство
  не меняется, поэтому чекпоинты PiSA-SR и учитель CSD с новым декодером совместимы.
- Результаты: `curve_vae.csv`, `bands_vae.csv`, `train_log_vae.csv`, `curve_vae.png`,
  `checkpoints/vae_decoder_final.pt` (около 200 МБ) и `vae_decoder_last.pt` (перезаписывается при каждой валидации).
  Строка шага 0 в `curve_vae.csv` — исходный потолок VAE, расчёт тот же, что в `diag_vae_ceiling.py`.
- С `VAE_DEC` эксперименты E00–E15 пишутся в папку с окончанием `_vaedec`.
- Калибровка весов (`AUTO`) здесь считается относительно суммарного градиента L1 + LPIPS.

## Что нужно знать

- **Веса потерь.** Стартовые значения в `experiments.sh` подобраны по нормам градиента на бикубическом тесте.
  По умолчанию включена калибровка (`AUTO=0.3`): перед этапом вес каждого частотного члена выставляется так,
  чтобы норма его градиента составляла 30 % от главного члена этапа (L2 в pix, LPIPS в sem).
- **Валидация** идёт каждые `EVAL_EVERY` шагов (по умолчанию 500) на 100 фиксированных снимках. Число шагов
  фиксировано, в работу идёт чекпоинт последнего шага; кривая нужна только для проверки сходимости.
- **Две видеокарты.** Учитель CSD, RAM и VGG для FDL автоматически переносятся на `cuda:1`, если она есть.
- **Память.** FDL по умолчанию считается в окне 256×256 (`FDL_CROP=256`). Расход памяти пишется в `curve_*.csv`.
- **Ранг LoRA 8** (`--lora_rank_unet_pix 8 --lora_rank_unet_sem 8`) нельзя стартовать с релизного чекпоинта
  ранга 4: веса не загрузятся, обучение пойдёт с нуля.
- **Допущения реализации.** В карте деталей три отклика нормируются на свой максимум (в FiDeSR нормировка
  не описана). В FDL по полосам к ВЧ-составляющей прибавляется 0,5, чтобы вход VGG оставался в диапазоне
  изображения. В Fourier Space Loss БПФ берётся без нормировки.
- **Не реализовано:** VAE-D4, блок LRRB, контрастная дистилляция RS-AdaDiff.

## Состояние проверки

Потери, метрики и диагностика проверены на CPU на снимках из `HQ_Val`. `train_freq.py` проходит оба этапа
на CPU с заглушкой вместо модели. На GPU с настоящей PiSA-SR код не запускался: `infer_eval.py`,
`diag_vae_ceiling.py`, режим fp16 и работа на двух видеокартах не проверены.

К6: `train_vae_decoder.py` прошёл на CPU с настоящим VAE SD 2.1 (кроп 128, несколько шагов, все члены потерь);
подстановка декодера проверена в `diag_vae_ceiling.py` и в VAE с тайловым хуком из `PiSASR_eval`.
`train_freq.py --vae_decoder_ckpt` и обучение декодера на GPU не запускались.

Совместимость с новой `diffusers` (проверено на 0.43 и peft 0.20, CPU, UNet со случайными весами): модули
импортируются, LoRA-адаптеры создаются, градиент доходит до LoRA, инференс `PiSASR_eval` совпадает с обучающим
режимом до 1e-5. Правки — в `src/models/unet_2d_condition.py` и `src/models/autoencoder_kl.py`.
